# Руководство для разработчиков и ИИ-агентов

## GitHub Actions — обязательный локальный runner

- Все существующие и новые задания GitHub Actions, включая сборки, тесты и проверки PR, выполняются **только** на Windows self-hosted runner владельца проекта.
- В каждом обычном job указывать строго: `runs-on: [self-hosted, Windows, X64]`.
- Не использовать `ubuntu-latest`, `ubuntu-24.04`, `windows-latest`, `macos-latest`, GitHub-hosted runners, динамические `runs-on` и переиспользуемые workflow, запускающие jobs в облаке.
- Использовать Windows-совместимые команды (PowerShell/cmd либо Git Bash при явном требовании) и уже установленный на локальном компьютере инструментарий. Не подменять платформу простой заменой `runs-on`, если скрипты Linux-зависимы.
- Перед первым запуском в **каждом репозитории** убедиться, что к нему подключён локальный runner с метками `self-hosted`, `Windows`, `X64`. Если runner недоступен, job должен ожидать, а не переходить в облако.
- Не запускать недоверенный код из Pull Request на компьютере владельца: для сборок по PR разрешено выполнение только после проверки владельцем. Если нужен аудит PR через `pull_request_target`, не делать checkout ветки PR, не запускать её скрипты и не передавать недоверенные значения в исполняемый код.
- При добавлении или изменении .github/workflows проверять соблюдение этой политики до слияния. Не менять игровой код ради настройки CI.
